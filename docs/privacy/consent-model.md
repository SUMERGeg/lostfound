# Модель согласий Lost&Found

Дата технической реализации: 13 августа 2026 г.

## Текущие типы и версии

| Тип | Техническая версия | Статус |
|---|---|---|
| `TERMS` | `terms-draft-2026-08-13.1` | Черновик, не утверждён владельцем |
| `PERSONAL_DATA` | `personal-data-draft-2026-08-13.1` | Черновик, не утверждён владельцем |

Регистрация требует два независимых действия. Checkbox не отмечены заранее. Клиент отправляет тип, `accepted: true` и точную версию; сервер самостоятельно сравнивает её с текущим каталогом и в одной транзакции создаёт пользователя и две строки `user_consents`.

## Старые пользователи

Миграция `008_user_consents` только создаёт таблицу. Она **не** добавляет старым, demo или test пользователям записи согласий и не выводит согласие из `email_verified_at`, регистрации или использования сервиса. Их состояние — `consent missing`.

До production-запуска нужен отдельный re-consent flow: показать утверждённые финальные редакции, получить два самостоятельных действия и записать новые версии. Автоматически принимать документы от имени пользователя запрещено.

## Минимизация доказательств

Сохраняются user ID, тип, версия, время, источник и возможное время отзыва. IP и User-Agent в `user_consents` не сохраняются: владелец пока не утвердил цель, форму минимизации и срок хранения этих атрибутов. Сессионный User-Agent существует отдельно и не считается доказательством согласия.

## Production-блокер

Версии с `draft` предназначены для технической проверки. Перед публичным запуском владелец должен заполнить реквизиты и юридические placeholders, утвердить текст и выпустить новые финальные версии с датой вступления в силу. После смены текущей версии backend будет отклонять старую версию в новых регистрациях.

## OpenAPI lint baseline

Consent request описан в `openapi.yaml`. Проектный `redocly.yaml` оставляет включённой проверку структуры, схем и `$ref`, но временно отключает шесть стилевых правил для старых endpoint: обязательные `summary`, явный `security`, license, production server URL, неоднозначные шаблоны путей и обязательный 4xx response. Это существующий долг всего контракта, а не исключение для consent; его следует закрывать по мере документирования старых маршрутов.
