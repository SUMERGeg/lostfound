# Обращения по персональным данным

Дата реализации: 16 августа 2026 г.

## Пользовательский сценарий

Публичная страница `/privacy-request` принимает обращения пяти типов: доступ, исправление, удаление, отзыв согласия и другой вопрос. Вошедший пользователь отправляет запрос с email активного аккаунта; значение email из тела запроса в этом случае игнорируется. Посетитель без аккаунта обязан указать корректный email.

Ответ публичного API содержит только номер обращения и статус `NEW`. Email и текст запроса обратно не возвращаются. На один IP действует ограничение `PRIVACY_REQUEST_RATE_LIMIT_MAX` обращений в час (по умолчанию — 5).

Контакт оператора задаётся переменной `PRIVACY_EMAIL` и публикуется через `GET /api/v1/privacy-requests/config`. Пока владелец не заполнил значение, интерфейс намеренно показывает `[PRIVACY_EMAIL]`, не создавая неработающую ссылку `mailto:`.

## Работа оператора

Очередь доступна только роли `ADMIN` в разделе «Персональные данные» панели модерации. Разрешённые переходы:

- `NEW` → `IN_PROGRESS`, `RESOLVED` или `REJECTED`;
- `IN_PROGRESS` → `RESOLVED` или `REJECTED`;
- терминальные статусы повторно не изменяются.

Каждая смена статуса записывается в `audit_log` как `PRIVACY_REQUEST_STATUS_CHANGED`. В аудит попадает только новый статус: email, сообщение и служебная заметка туда не копируются.

## Обязательные организационные решения

Система регистрирует и маршрутизирует запрос, но не автоматизирует юридически значимую проверку личности и выдачу данных. До production-выпуска владелец сервиса должен утвердить и документировать:

1. способ проверки личности для каждого типа запроса;
2. сроки первичного ответа и исполнения;
3. правила выгрузки и безопасной доставки копии данных;
4. основания для отказа или продления срока;
5. сроки хранения обращений, заметок и audit trail;
6. фактический адрес `PRIVACY_EMAIL` и ответственных сотрудников.

Значения остаются связанными с решениями из [owner-decisions-required.md](./owner-decisions-required.md); код не подменяет их юридическими предположениями.

## Удаление аккаунта

При удалении аккаунта связанные обращения сохраняют операционный статус, но теряют связь с пользователем, email, исходный текст и служебную заметку. Поля заменяются privacy-safe значениями, а ссылка `resolved_by` очищается при удалении аккаунта администратора. Окончательный срок удаления самой записи должен быть установлен общей retention policy.

## API

- `GET /api/v1/privacy-requests/config` — публичный контакт оператора;
- `POST /api/v1/privacy-requests` — регистрация обращения, авторизация необязательна;
- `GET /api/v1/admin/privacy-requests` — очередь администратора с необязательным фильтром `status`;
- `PATCH /api/v1/admin/privacy-requests/{id}` — смена статуса.

Полные контракты находятся в корневом [openapi.yaml](../../openapi.yaml).
