# Демонстрационная витрина на Vercel

Это автономная версия только для просмотра. Лента, фильтры, карточки и условная схема Москвы используют вымышленные данные и изображения из `client/public/sample`. Регистрация, публикация, загрузки и все отправки форм отключены. Настоящий API, база данных и хранилище не развёртываются.

## Публикация от начала до конца

1. Отправьте изменения деморежима в GitHub. Vercel собирает код из репозитория, а не локальные файлы компьютера.
2. Войдите на https://vercel.com через GitHub.
3. Выберите **Add New → Project**, найдите **SUMERGeg/lostfound** и нажмите **Import**. Если репозиторий не виден, разрешите доступ через **Configure GitHub App**.
4. Назовите проект, например `lostfound-demo`.
5. В **Root Directory → Edit** выберите **client**. Это путь внутри GitHub-репозитория; `product-source` указывать не нужно.
6. Укажите **Framework Preset: Vite**. Настройки уже заданы в `client/vercel.json`:

   | Настройка | Значение |
   |---|---|
   | Install Command | `npm ci` |
   | Build Command | `npm run build:demo` |
   | Output Directory | `dist` |

   Если эти поля переопределены в панели Vercel, выставьте значения из таблицы. Не заменяйте сборку на `npm run build`: это обычная версия, которой нужен backend.

7. **Environment Variables оставьте пустыми.** Демонстрации не нужны API URL, ключ карты, JWT-секреты, MySQL, S3 или почтовый провайдер. Карта — подписанная интерактивная схема, не настоящая географическая карта.
8. Нажмите **Deploy** и дождитесь успешной сборки. Откройте основной адрес проекта через **Visit**.
9. В **Settings → Git** проверьте **Production Branch: main** (если деморежим опубликован именно в `main`).
10. Откройте основной адрес в режиме инкогнито. Если Vercel требует авторизацию, проверьте **Settings → Deployment Protection** и разрешите публичный доступ к этому демонстрационному проекту. Отправляйте посетителям основной адрес проекта, а не защищённую preview-ссылку.

## Что проверить

- `/ads`: пять объявлений с изображениями, работающие фильтры.
- `/ads/demo-phone`: карточка открывается напрямую и после обновления страницы.
- `/map`: точки переключают карточку; фильтры меняют набор точек.
- `/register`, `/create/lost`, `/privacy-request`, `/ads/demo-phone/claim`: перенаправляют на ленту, форм нет.
- Нет сообщений об ошибке загрузки API, запросов к `/api` и кнопок отправки данных.
- На телефоне нет горизонтального переполнения.

Пример основного URL: `https://lostfound-demo.vercel.app`. Фактический адрес выдаст Vercel.

## Локальный просмотр

Из папки `client`:

```powershell
npm ci
npm run dev:demo
```

Для просмотра именно опубликованной сборки:

```powershell
npm run build:demo
npm run preview
```

Backend запускать не нужно. Не запускайте seed или миграции для этой витрины.

## Обновления и обычный сервис

После push в production-ветку Vercel автоматически пересоберёт витрину, если включён Git auto-deploy. Вымышленные объявления находятся в `client/src/demo.js`.

Обычная разработка и Docker-сборка по-прежнему используют `npm run dev` и `npm run build`. Деморежим включается только при `--mode demo` или `VITE_DEMO_MODE=true`. При переключении на настоящий сервис понадобится отдельный deployment с backend и другой командой сборки.

Документация платформы: https://vercel.com/docs/frameworks/frontend/vite и https://vercel.com/docs/git/vercel-for-github.
